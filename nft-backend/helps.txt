When do you need it?
Deploying to cloud (AWS, GCP, DigitalOcean, Render)
Want consistent environment (no “works on my machine” issues)
Minimum steps
Create a Dockerfile in your project root:
FROM node:20

WORKDIR /app

COPY package*.json ./
RUN npm install

COPY . .

RUN npm run build

CMD ["node", "dist/server.js"]


Build the image:
docker build -t nexvel-backend .
Run it:
docker run -p 4000:4000 \
  -e DATABASE_URL=... \
  -e REDIS_URL=... \
  -e JWT_SECRET=... \
  nexvel-backend

👉 Now your app runs inside Docker at http://localhost:4000.




Do you have to use Docker?

No. It’s recommended for production, but you can deploy without it (using PM2 below).

⚙️ 10) PM2 — “keep your server running 24/7”

What it does:
Runs your Node app as a process manager:

Restarts if it crashes
Keeps it running after server reboot
Can run multiple instances (scaling)
When do you need it?
You deploy on a VPS (Ubuntu, EC2, etc.)
You want uptime without babysitting
Setup PM2 (super simple)
Install globally:
npm install -g pm2
Build your app:
npm run build
Start your server:
pm2 start dist/server.js --name nexvel
Save process (auto-restart on reboot):
pm2 save
pm2 startup
Useful PM2 commands
pm2 list        # see running apps
pm2 logs        # view logs
pm2 restart nexvel
pm2 stop nexvel
🧠 Simple analogy
Docker = your app in a sealed box (portable everywhere)
PM2 = a supervisor that keeps your app alive
